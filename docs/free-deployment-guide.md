# 台球追分项目的免费部署方案

> 信息核对日期：2026 年 10 月 14 日。平台套餐和额度可能调整，请以官方说明及账号控制台为准。

这个项目采用 **GitHub + Render + Neon** 部署。在各平台的免费额度内，可以做到 **每月 0 元**，无需购买服务器或域名，并支持多人使用各自的手机实时记分。

- 项目体验：[追分网站](https://zhuifen-web-lighto00o3.onrender.com/)
- 项目源码：[GitHub 仓库](https://github.com/Lighto00o3/zhuifen)

## 1. 部署架构

| 部分 | 技术与平台 | 作用 |
| --- | --- | --- |
| 代码托管 | GitHub | 保存前后端代码，管理分支与合并 |
| 网页前端 | Vue 3 + Nuxt，部署到 Render Static Site | 提供手机和电脑上的操作页面 |
| 后端服务 | NestJS，部署到 Render Free Web Service | 管理房间、处理记分和 Socket.IO 实时同步 |
| 数据库 | Neon Free PostgreSQL | 保存联机比分与历史对局 |
| 自动检查 | GitHub Actions | 运行测试和构建，检查通过后由 Render 自动部署 |
| 访问地址 | Render 默认域名与 HTTPS | 使用 `onrender.com` 地址，不需要另外购买域名 |

```text
手机 / 电脑浏览器
        │
        ▼
Render 静态前端（Vue 3 + Nuxt）
        │
        │ HTTP 请求 / Socket.IO 实时连接
        ▼
Render 免费后端（NestJS，新加坡）
        │
        ▼
Neon 免费数据库（PostgreSQL，新加坡）
```

Nuxt 在这套方案中生成静态 SPA，由浏览器运行页面。前端不需要额外启动 Nuxt 服务端进程，因此可以使用免费的静态站点托管。

Render 提供免费静态站点、免费后端实例、默认访问地址及托管 HTTPS。参见：[免费部署说明](https://render.com/docs/free)、[静态站点说明](https://render.com/docs/static-sites)、[默认地址说明](https://render.com/docs/your-first-deploy)。

## 2. 多人实时记分如何工作

1. 一名球友创建双人或三人房间，将房间号或二维码分享给其他人。
2. 其他球友使用自己的手机和网络加入，无需连接同一个 Wi-Fi。
3. 输家在自己的手机上操作给分，后端计算积分变化并写入数据库。
4. 后端通过 Socket.IO 广播最新比分，所有人的手机同步更新。

联机模式的比分与历史记录保存在 Neon 数据库中，不依赖 Render 后端的临时文件系统。后端重启后可以从数据库恢复房间。

单机模式的记录保存在当前浏览器，记分不使用后端数据库。页面加载完成后可以断网记分，但首次打开或离线刷新仍需要网络加载页面资源；清除浏览器数据会删除单机记录。

## 3. 首次部署需要做什么

1. 将代码上传到 GitHub。
2. 注册 Render，并授权其读取项目仓库。
3. 注册 Neon，创建免费 PostgreSQL 项目，选择与后端接近的区域。
4. 使用仓库根目录的 `render.yaml` 创建前端静态站点和免费后端服务。
5. 在 Render 配置环境变量：

   | 服务 | 环境变量 | 内容 |
   | --- | --- | --- |
   | 后端 | `DATABASE_URL` | Neon 提供的数据库连接字符串，保留 TLS 参数 |
   | 后端 | `CORS_ORIGINS` | 前端的实际 HTTPS 地址 |
   | 前端 | `NUXT_PUBLIC_API_ORIGIN` | 后端的实际 HTTPS 地址，不带 `/api` 后缀 |
   | 前端 | `NUXT_SPA` | `true`，生成静态 SPA |

6. 将两个服务的自动部署设为 **After CI Checks Pass**，部署分支选择 `main`。
7. 检查后端健康接口，再用两台或三台手机验证创建、加入、给分、撤销和刷新恢复。

数据库连接字符串包含密码，只配置在平台环境变量中，不提交到 GitHub。

该项目已经完成上述配置；其他人复用仓库时，需要使用自己的账号、数据库和服务地址。具体构建命令及静态站点路由规则已写在 `render.yaml` 中。

## 4. 新功能如何自动上线

项目已经配置以下流程：

```text
开发新功能
    ↓
提交代码并创建 PR
    ↓
合并到 main
    ↓
GitHub Actions 自动测试与构建
    ↓
检查通过
    ↓
Render 自动发布前端和后端
```

GitHub 负责代码和自动检查，Render 负责运行网站及后端。完成一次性授权和配置后，每次更新无需手动上传文件或登录服务器执行部署命令。

公开仓库使用标准 GitHub 托管运行器时，Actions 运行时间免费；私有仓库、较大运行器及存储使用有不同的额度和计费规则。参见：[GitHub Actions 计费说明](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。

## 5. 免费额度与使用限制

### Render 后端

- 连续 **15 分钟**没有入站 HTTP 请求或 WebSocket 消息时，免费后端会休眠。
- 再次收到请求或新的 WebSocket 连接时会唤醒，官方说明通常需要约 **一分钟**。
- 每个工作区每月共享 **750 小时**免费实例运行时间，多个免费后端会共用这份额度。
- 流量和构建时间也有额度。超额时，有付款方式的账号可能产生费用；没有付款方式时，可能暂停服务或停止新的构建。
- 免费后端可能因平台重启或部署暂时断开连接，客户端需要重连。

前端是静态站点，不受后端休眠影响，但创建房间、联机给分等操作需要等待后端可用。

参见：[Render 免费服务限制](https://render.com/docs/free)。

### Neon 数据库

截至核对日期，每个免费项目包含：

| 项目 | 免费额度 |
| --- | --- |
| 数据库存储 | 1 GB |
| 数据库计算 | 每月 100 CU-hours |
| 公网传出流量 | 每月 5 GB |

CU-hours 是计算资源大小与运行时间的乘积，不等同于数据库只能使用 100 小时。例如以 0.25 CU 运行，100 CU-hours 约对应 400 小时的计算运行时间。

免费数据库闲置约 5 分钟后，计算资源自动暂停，以节省额度；这不会删除数据库里的比分与历史记录。计算、存储和网络使用仍需关注免费额度。

选择 Neon 的原因之一是：Render 免费 PostgreSQL 数据库创建后 **30 天到期**，不适合在这套方案中长期保存对局记录。

参见：[Neon 当前套餐](https://neon.com/pricing)、[Render 免费数据库限制](https://render.com/docs/free)。

### 国内访问体验

本项目后端和数据库选择新加坡区域。国内不同地区、运营商和网络环境的访问速度可能不同，需要使用真实手机流量测试，不能保证所有用户都流畅访问。

## 6. 适合什么项目

这套方案适合个人项目、演示、课程作业，以及早期小规模试用。它可以低成本部署包含网页、后端、数据库和实时同步的完整项目，并实现合并代码后自动上线。

“免费”指使用量处于平台免费额度内，不代表无限流量、永不休眠或长期高负载仍然免费。用户量增长，或需要持续可用和更稳定的国内访问体验时，再评估付费服务或国内服务器。
