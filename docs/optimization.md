# 缺陷与优化清单

2026-10-14 对项目做的一次整体梳理。完成一项就打勾，并注明对应的提交。

## 一、缺陷

- [x] **1. 局域网 HTTP 下单机模式无法开局**
  单机模式直接调用 `crypto.randomUUID()`，但手机用 `http://192.168.x.x` 打开时这个接口不可用，一点开局就报错。
  已改为 `app/utils/random.ts` 里的 `randomId()` / `randomHex()`，联机和单机共用。（`2b40689`）
- [x] **3. 本机历史没有上限**
  单机历史和联机历史缓存只增不减，localStorage 写满后连当前这一局都存不下。
  已改为各保留最近 50 场（`MAX_LOCAL_GAMES` / `MAX_ONLINE_GAMES`）。注意：单机记录超过 50 场后，最早的会被永久删除。（`2b40689`）
- [x] **4. 接口返回非 JSON 时报错不可读**
  网关返回 502/504 的 HTML 页面时，用户会看到 `Unexpected token <`。
  现在会提示「服务暂时不可用」；遇到 5xx 时保留这笔操作，可以重试。（`2b40689`）
- [x] **5. CORS 配置没有去空格，且写了两份**
  `"a.com, b.com"` 中第二个域名会匹配失败。现在统一在 `env.ts` 的 `corsOrigins` 里解析，HTTP 接口和 WebSocket 共用。（`a9a1949`）
- ~~**2. 三人局大金、黄金9 的读屏文案与计分不一致**~~ —— 撤回。按规则，两位输家各付一笔，「每人给 X 分，共 2X 分」是对的。

## 二、待确认的规则问题

- [x] **三人局普胜、小金的收分人**
  按规则，输家一定是赢家的上家，所以收分人只能是输家的下家。现在却让输家自己选，服务端也只校验收分人不是本人（`rooms.ts`，`score` 分支）。
  备选方案：前端改为一键给下家；服务端校验 `recipientId` 必须是下家。现场是否会出现不按顺序的情况？需要确认后再改。

## 三、安全与稳定性

- [ ] **6. 接口没有限流**
  创建房间可以被刷爆；加入房间只需要 6 位房间号，可以暴力枚举。
  初步方案：同一 IP 每分钟最多创建 10 个房间、加入 20 次。部署在 Caddy 或 Nginx 后面时，要开启 `trust proxy` 才能拿到真实 IP。
- [ ] **7. 数据只增不减**
  `rooms` 和 `room_commands` 永久保留。需要定期清理长时间没有更新的房间，并给 `updated_at` 加索引。
  要先定下保留天数，因为删掉房间会导致服务端的联机历史一起消失。
- [ ] **8. 不能多实例部署**
  在线状态 `presence` 存在进程内存里，广播也只发给本进程。目前单实例没问题；以后扩容要接 `@socket.io/redis-adapter`，并在部署文档里写明这个限制。
- [ ] **9. 没有数据库迁移机制**
  表结构是启动时用 `CREATE TABLE IF NOT EXISTS` 建的，以后改表结构没法平滑升级。

## 四、性能

- [ ] **10. 房间状态越来越大**
  所有局的 `rounds` / `events` 都存在同一个 JSONB 字段里。每记一笔分都要重写整份状态，广播和 GET 也会带上全部历史局。
  方案：历史局拆到单独的表，实时只推当前这一局，历史按需拉取。
- [x] **11. 幂等检查多查了一次**
  两次查询已合并为一次。（`a9a1949`）
- [ ] **12. 单机每次保存都要校验全部历史**
  `storeLocalGame` 每次都会重新完整校验所有历史记录。历史已限制在 50 场，开销有了上限；这层校验又能防止覆盖损坏的记录，所以暂时不改。
- [x] **13. 联机记分时反复重写历史缓存**
  现在只在房间、状态或已结束局数变化时才写入。（`a9a1949`）
- ~~**14. 创建或加入房间时多建一次连接**~~ —— 撤回。扫码进入 `/room?room=X` 后直接加入时，页面不会重新挂载，这里的 `connect()` 是必需的。

## 五、可维护性

- [ ] **15. 前端直接引用后端源码**
  前端里写的是 `../../../api/src/model`。建议抽出 `packages/shared` 包，放类型、规则和 `scoreDeltas`。
- [x] **16. 同样的代码写了多份**
  `ScoreApp.vue` 和 `local.vue` 改为共用 `LABELS`、`DEFAULT_RULES`、`CARD_SUITS`（`utils/pointCards.ts`），以及 `formatElapsed` / `clockTime`（`utils/format.ts`）；随机 ID 在 `2b40689` 中已合并。（未提交）
- [ ] **17. `ScoreApp.vue` 过大**
  有 400 多行，首页、房间页、弹窗、socket、命令队列全在一个组件里。建议拆出 `useRoom()` 组合函数和各个弹窗组件，焦点管理、滚动锁定也抽成公共的组合函数。
- [ ] **18. 测试覆盖不足**
  已补：随机 ID、历史上限（`2b40689`）；用时格式化、扑克牌拆分、联机历史与输赢计算（`test/utils.test.ts`，未提交）。
  还缺：`receive()` 的增量动画逻辑，以及 `api()` 对非 JSON 响应的处理，这两处都在组件里，要先拆出 `useRoom()`（第 17 条）才好测。
